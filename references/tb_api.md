# tb_api — DE-friendly task BFM (gen-tb reference)

> Loaded during Phase 4 scaffolding. This file defines the canonical
> `tb_api::` package contents and the SystemVerilog patterns used
> inside it. The DE persona drives the tb through these tasks; the DV
> persona uses normal UVM sequences. Both share the same primitives.

## Why this file exists

The uart16550 dry-run exposed a real APB sampling bug: a hand-rolled
`apb_read` task returned wrong data because of a one-cycle sampling race
against the DUT's registered output. **gen-tb must not let each
invocation reinvent the APB read primitive** — it's load-bearing for
every generated tb's sanity test.

This file provides the APB *known-good* implementation. For
`bus_protocol: ahb` and `bus_protocol: axi_lite`, `scripts/scaffold.py`
emits the matching variant described in `references/ahb.md` /
`references/axi_lite.md` with the same public
`tb_api::write/read/expect_reg` surface. Generation only parameterizes
the package header and selects the bus-specific primitive body. The
AHB read primitive samples `hrdata` after `hready` has settled to avoid
the same-cycle NBA race seen in the reused AHB VIP flow. The AXI4-Lite
primitives use `@(posedge clk iff valid && ready)` inside a fork-join
to track the AW/W/B and AR/R handshakes without racing the responder.

For `bus_protocol: ahb` or `axi_lite` with `bus_direction: master`
(DUT is master), `tb_api::` exposes responder-side helpers instead of
write/read: `seed_mem`, `peek_mem`, `wait_for_write`, `wait_for_read`,
`expect_observed_write`, and `clear_observed`. The shared `_mem`
associative array and `*_observed` counters are updated by the
generated slave responder driver; tests poll them to assert what the
DUT initiated. Both AHB-Lite and AXI4-Lite use the same helper
surface; only the underlying responder state machine differs.

## Package skeleton

`tb/tb_api/tb_api_pkg.sv` always has this exact shape:

```systemverilog
`ifndef TB_API_PKG_SV
`define TB_API_PKG_SV

package tb_api;
    import uvm_pkg::*;
    `include "uvm_macros.svh"

    // ---- compile-time parameters injected from intake.yaml ----
    parameter int  ADDR_W            = {{paddr_width_or_haddr_width}};
    parameter int  DATA_W            = 32;
    parameter int  DEFAULT_TIMEOUT_NS = 100_000;

    // ---- virtual interface handle (set once at start_of_simulation) ----
    typedef virtual <bus>_if #(.ADDR_W(ADDR_W), .DATA_W(DATA_W)) vif_t;
    vif_t vif;

    function automatic void set_vif(vif_t v);
        vif = v;
    endfunction

    // ---- primitives (DO NOT EDIT in generated output) ----
    `include "tb_api_primitives.svh"
endpackage

`endif
```

The primitives live in a separate `.svh` so gen-tb's regeneration of
the package header (parameters, address maps) never touches the
load-bearing task bodies.

## Primitives (`tb_api_primitives.svh`)

For APB, this is the canonical body. Comments explain
*why* each line matters; do not strip them.

```systemverilog
// =====================================================================
// tb_api primitives — known-good APB master + status helpers.
// Generated by gen-tb. Body is NOT regenerated on intake.yaml change;
// only the package header (ADDR_W/DATA_W/addr constants) is.
// =====================================================================

// --- assertion gates -----------------------------------------------
function automatic void _require_vif();
    if (vif == null) `uvm_fatal("TB_API", "vif not set — call tb_api::set_vif(...) in start_of_simulation_phase")
endfunction

// --- single-word APB write -----------------------------------------
// Cycle pattern:
//   T+0  posedge → drive SETUP signals  (psel=1, penable=0)
//   T+1  posedge → drive ACCESS signals (psel=1, penable=1)
//   T+1+ posedge → wait until pready==1, then ONE MORE posedge before
//                  deasserting. The extra cycle prevents a back-to-back
//                  read from sampling the previous transaction's
//                  registered prdata path (this bit us in uart16550).
task automatic write(input logic [ADDR_W-1:0] addr,
                     input logic [DATA_W-1:0] data);
    _require_vif();
    @(posedge vif.pclk);
    vif.psel    <= 1'b1;
    vif.penable <= 1'b0;
    vif.pwrite  <= 1'b1;
    vif.paddr   <= addr;
    vif.pwdata  <= data;
    @(posedge vif.pclk);
    vif.penable <= 1'b1;
    // Wait until ready. `do @; while` style ensures we sample on the
    // posedge, not in the active region of the previous cycle.
    do @(posedge vif.pclk); while (vif.pready !== 1'b1);
    vif.psel    <= 1'b0;
    vif.penable <= 1'b0;
    vif.pwrite  <= 1'b0;
endtask

// --- single-word APB read ------------------------------------------
// Same timing contract as write(). The critical detail: prdata is
// sampled at the posedge where pready is observed to be 1. If the
// DUT's prdata is registered with the same clock, this is the cycle
// the registered value becomes visible — sampling here is correct.
// If the DUT registers prdata one cycle later than pready (rare but
// possible), the wait loop will still loop once more because pready
// will already be high again — which doesn't happen on a one-shot
// pattern. If you hit this case, set TB_API_EXTRA_READ_CYCLE=1 in
// the makefile and recompile; the extra delay is gated by `ifdef.
task automatic read(input  logic [ADDR_W-1:0] addr,
                    output logic [DATA_W-1:0] data);
    _require_vif();
    @(posedge vif.pclk);
    vif.psel    <= 1'b1;
    vif.penable <= 1'b0;
    vif.pwrite  <= 1'b0;
    vif.paddr   <= addr;
    @(posedge vif.pclk);
    vif.penable <= 1'b1;
    do @(posedge vif.pclk); while (vif.pready !== 1'b1);
`ifdef TB_API_EXTRA_READ_CYCLE
    @(posedge vif.pclk);
`endif
    data = vif.prdata;
    vif.psel    <= 1'b0;
    vif.penable <= 1'b0;
endtask

// --- multi-word array writes (registers.yaml `array_of: N`) -----
// Used for KEY0..N, BLOCK0..N etc. base = address of element 0,
// stride = byte-offset between elements (typically 4 for 32-bit regs).
task automatic write_array(input logic [ADDR_W-1:0] base,
                            input int                stride,
                            input logic [DATA_W-1:0] data[]);
    int i;
    for (i = 0; i < data.size(); i++) write(base + i*stride, data[i]);
endtask

task automatic read_array(input  logic [ADDR_W-1:0] base,
                           input  int                stride,
                           input  int                count,
                           output logic [DATA_W-1:0] data[]);
    int i;
    data = new[count];
    for (i = 0; i < count; i++) read(base + i*stride, data[i]);
endtask

// --- expect_reg: positive sanity primitive --------------------------
task automatic expect_reg(input logic [ADDR_W-1:0] addr,
                          input logic [DATA_W-1:0] expected,
                          input string             tag = "EXPECT");
    logic [DATA_W-1:0] got;
    read(addr, got);
    if (got !== expected)
        `uvm_error(tag, $sformatf("@0x%0h got=0x%08h expected=0x%08h",
                                  addr, got, expected))
    else
        `uvm_info(tag, $sformatf("@0x%0h = 0x%08h ✓", addr, got), UVM_LOW)
endtask

// --- reset: drive presetn low for N cycles --------------------------
// Most TBs drive presetn from the top, not from tb_api. This helper
// exists for DE-style directed tests that want to re-reset mid-sim.
// It uses `force`/`release` so the top's initial reset block doesn't
// race with it.
task automatic reset(input int cycles = 16);
    _require_vif();
    force vif.presetn = 1'b0;
    repeat (cycles) @(posedge vif.pclk);
    release vif.presetn;
endtask

// --- wait_status_flag: poll a bit until it matches expected --------
// Handles the "READY=1 at reset" pitfall (G29 from aes128 dry-run).
// When `wait_low_first=1`, the helper first waits for the bit to drop
// to 0 (DUT acknowledged the command and went busy) THEN back to 1
// (DUT done). This is the right pattern for "start an operation and
// wait for completion" on cores whose status flags start asserted.
task automatic wait_status_flag(
    input  logic [ADDR_W-1:0] status_addr,
    input  int                bit_idx,
    input  bit                expected = 1'b1,
    input  bit                wait_low_first = 1'b0,
    input  int                timeout_polls = 1000,
    input  string             tag = "WAIT");
    int  n;
    logic [DATA_W-1:0] rdata;
    if (wait_low_first) begin
        n = timeout_polls;
        do begin
            read(status_addr, rdata);
            if (rdata[bit_idx] !== ~expected) break;
            if (--n == 0) `uvm_fatal(tag, "timeout waiting for status bit to drop (busy ack)")
        end while (1);
    end
    n = timeout_polls;
    do begin
        read(status_addr, rdata);
        if (rdata[bit_idx] === expected) return;
        if (--n == 0) `uvm_fatal(tag, $sformatf("timeout waiting for bit %0d == %0d", bit_idx, expected))
    end while (1);
endtask

// --- wait_ns: simple cycle-independent delay ------------------------
task automatic wait_ns(input int ns);
    #(ns * 1ns);
endtask
```

## How the generated tb consumes tb_api

Three integration points:

### 1. Top-level `set_vif` handoff

In `<ip>_tb_top.sv` (generated), after the `uvm_config_db` set:

```systemverilog
initial begin
    uvm_config_db#(virtual apb_if)::set(null, "*", "apb_vif", apb);
    tb_api::set_vif(apb);                     // ← always emit this
    run_test();
end
```

### 2. Sanity test using `tb_api::expect_reg`

Generated `<ip>_sanity_test.sv`:

```systemverilog
class {{ip}}_sanity_test extends uvm_test;
    `uvm_component_utils({{ip}}_sanity_test)
    function new(string n="{{ip}}_sanity_test", uvm_component p=null); super.new(n,p); endfunction
    task run_phase(uvm_phase ph);
        ph.raise_objection(this);
        wait (tb_api::vif.presetn === 1'b1);
        repeat (4) @(posedge tb_api::vif.pclk);
        tb_api::expect_reg(.addr({{sanity_addr}}), .expected({{sanity_value}}), .tag("SANITY"));
        ph.drop_objection(this);
    endtask
endclass
```

`sanity_addr` / `sanity_value` come from registers.yaml: the first RO
register with a non-zero reset (e.g., uart16550 LSR=0x60 wait — see
note below — or aes128 NAME0="aes "). If no such reg exists, fall back
to register 0 with `expected=0` plus an extra `wait_status_flag` on a
known-asserted bit.

### 3. DE persona usage (no UVM sequence required)

A DE engineer can write directed tests in a separate file
(`test/de_<name>_test.sv`) that look like classic Verilog bench code:

```systemverilog
class de_uart_loopback extends uvm_test;
    `uvm_component_utils(de_uart_loopback)
    function new(string n="de_uart_loopback", uvm_component p=null); super.new(n,p); endfunction
    task run_phase(uvm_phase ph);
        ph.raise_objection(this);
        wait (tb_api::vif.presetn === 1'b1);
        // Configure baud + 8N1 + enable
        tb_api::write(12'h0C, 32'h83);     // LCR.DLAB=1, 8N1
        tb_api::write(12'h00, 32'd325);    // DLL = 9600 baud @ 50MHz
        tb_api::write(12'h0C, 32'h03);     // LCR.DLAB=0
        tb_api::write(12'h10, 32'h10);     // MCR.LOOP=1
        // Send byte
        tb_api::write(12'h00, 32'h55);
        // Wait for THRE to clear then re-assert
        tb_api::wait_status_flag(12'h14, 5, .expected(1'b1), .wait_low_first(1'b1));
        tb_api::expect_reg(12'h00, 32'h55, "LOOPBACK");
        ph.drop_objection(this);
    endtask
endclass
```

No sequence library, no driver, no virtual sequencer involved — yet
the test runs under UVM's `run_test()` so logging, phase, and report
infrastructure still work.

## What gen-tb regenerates vs preserves

| Region | Regenerated on each `gen-tb scaffold` | Preserved across runs |
|---|---|---|
| `tb_api_pkg.sv` header (parameters, addr constants) | yes | no |
| `tb_api_primitives.svh` (task bodies) | **only on `gen-tb refresh-primitives`** | yes by default |
| `de_*_test.sv` files in `test/` | never | yes |
| `<ip>_sanity_test` body | yes (regenerated from sanity_addr/value) | no |

The "primitives stay until you ask" rule means a user who has manually
patched a timing detail in tb_api won't have it stomped on a routine
re-scaffold.

## Known limitations (v1.1)

1. **No back-pressure on wait_status_flag**: if pready never goes
   high, the loop hangs the simulation rather than timing out. Fix:
   add a clock-cycle wall-clock timeout in addition to the poll
   timeout.

2. **Single APB master assumption**: tb_api owns the only `vif`. A
   multi-master / multi-port DUT needs the package re-templatized with
   a master ID parameter. Deferred.

3. **No randomization helpers**: DV persona uses sequences for that.
   tb_api is intentionally directed-only.

4. **Empirical timing on uart16550 still failing**: the v1 dry-run's
   apb_read returned 0 even with `do @; while` style. The above
   pattern includes the `do @; while (pready !== 1'b1)` form, but
   re-testing on uart16550 with this primitive is required to confirm
   the fix. If it still fails, set `TB_API_EXTRA_READ_CYCLE` and
   re-test before treating this file as canonical.

## Cross-references

- `references/apb.md` — the full APB agent generation (when reusing
  user VIP, or for DV-persona sequence work). tb_api is *not* an APB
  agent — it's a thin user-facing layer that happens to drive an APB.
- `references/refm_dpi.md` — DPI smoke tests use `tb_api::write_array`
  / `tb_api::read_array` for KEY/BLOCK/RESULT register groups.
- `references/ral_gen.md` — the RAL block is generated in parallel;
  it provides typed access for DV sequences. tb_api uses raw
  addresses because the DE persona prefers concrete numbers over
  named handles.
