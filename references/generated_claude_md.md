# Generated CLAUDE.md template (gen-tb reference)

> Loaded during Phase 7 hand-off. Defines the `CLAUDE.md` file written
> into each generated IP testbench directory.

## Purpose

`<ip>/CLAUDE.md` is for future agent sessions inside the generated
testbench. It should be concise, factual, and project-local. It must
tell the next agent what was generated, what is user-owned, how to run
tests, and what must not be edited.

Do not paste the whole skill into generated `CLAUDE.md`.

## Write Policy

Create `CLAUDE.md` on first scaffold. On later scaffold runs:

- preserve user-added sections when possible
- update the generated summary block only
- if preservation is not implemented, write `CLAUDE.md.new` and tell the
  user rather than silently clobbering edits

The generated file is user-editable after hand-off.

## Rules For Future Agents

- Do not edit user RTL, user VIP source, specs, or user reference-model
  source unless the user explicitly asks.
- Do not weaken sanity or register-access checks to make a run pass.
- Keep generated scoreboard code under `tb/scoreboard/`, not `test/`.
- Keep testcase classes and `sv_list` under `test/`.
- Treat register-level expected behavior as RAL/reg-block behavior.
- For external VIP reuse, generate project-local glue instead of
  patching the VIP source.

## Required Content

The generated file must mention:

- exact IP name and bus protocol
- generated tests and commands
- user-owned directories
- generated directories
- external VIP mode when present
- reference-model mode/trust when present
- RTL stub warning when `rtl_state: generated_stub`
- unresolved items and where to find logs

## Concision

Target 80-160 lines. Prefer links/paths to long explanations. Future
agents can read audit artifacts for details.
