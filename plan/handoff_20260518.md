### 5.2 生成 tb 的目录布局(用户看到的)

参照 `/home/robin/Projects/uart_uvm_demo` 的约定,**不可改**:

```
<ip>/
├── .prj_top                       # 标志位,setup.sh 向上查找
├── rtl/                           # 用户 RTL 在此(只读) / 或 gen-tb 生成 stub
├── ref_model/                     # 用户 C-DPI 源(只读)
├── script/{makefile, setup.sh, check_env.sh, design.f, tb.f}
├── top/<ip>_tb_top.sv
├── tb/{apb_if.sv, tb_api/, apb_agt_top/, ral/, dpi/}
├── test/{<ip>_pkg.sv, sv_list}
└── work/_gen_audit/               # 所有 phase 的 audit trail
```

### 5.3 命名规范(已经定型)

- 测试名:`<ip>_<purpose>_test`(从来不光裸 `sanity_test`)
- yaml offset:**post-wrapper PADDR**(用户视角的字节偏移)
- Makefile 文件名:lowercase `makefile`
- design.f 位置:**`script/design.f`**(不是 `rtl/design.f`)
- `tb/dpi/` 是**生成的** DPI 工件;`ref_model/` 是**用户输入**

### 5.4 跨阶段硬约束

| 约束 | 实现位置 |
|---|---|
| 不拷贝用户 RTL | scaffold.py 把 `$PROJ_DIR/rtl/...` 写进 design.f |
| 不改用户 RTL | sub-agent 提示词限制 |
| 不静默覆盖 | scaffold.py `--force` 必填,否则 atomic refuse |
| **不通过 symlink 写出 ip_root**(G17) | scaffold.py `_resolve_safely`(realpath 检查) |
| 不臆造寄存器 | RAL 1:1 从 registers.yaml 生成 |
| 零外部 skill 硬依赖 | check_env.sh 自检,不依赖 eda-environment / TraceWeave / skill-creator |

### 5.5 第三方 license

- 整个 skill: **Apache-2.0**
- aes128 fixture: BSD-2-Clause(secworks) + Unlicense(tiny-AES-c)→ release tarball **包含**
- uart16550 fixture: LGPL(OpenCores)→ release tarball **排除**(`.gitattributes` 中 `export-ignore`)

### 5.6 已知会保留的 v1.1 缺陷(不阻塞 ship)

- RAL 是空壳,reg_access_test 用 tb_api 直接遍历(见 ral_gen.md "What v1.1 emits")
- 没有完整 UVM agent(test 用 tb_api 直接驱动 vif)
- DPI 只支持 c_dpi,py_dpi 在 SKILL.md 中是 v1.2
- 协议只支持 APB
- 仿真器只支持 VCS
